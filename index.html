Read a link the way an attacker writes it

A link is more than the name you see first. TrustURL separates each part and tells you what it found.

https://Protocol accounts.example.com@Ignored by browsers 198.51.100.7Real destination /signinPath ?session=…Parameters

Example link for illustration. Everything before the @ sign is decoration: this link would open the numeric address, not a site called example.com.

  • HTTPS usage

    Whether the connection would be encrypted, and what that does and does not tell you.

  • Hostname structure

    Deep subdomains, long hyphenated names and look-alike international characters.

  • IP-address links

    Numeric addresses that hide who runs the site.

  • Misleading patterns

    Domain endings in the wrong place, embedded redirects and private-looking parameters.

  • Hidden credentials

    Text before an @ sign that disguises the real destination.

  • Reputation lookup

    Whether Google Safe Browsing already lists the address, when a key is configured.

How it works

  1. Paste a link

    Copy the address from a message, email or page without opening it.

  2. Run the security checks

    TrustURL inspects the address and asks a reputation service when one is configured.

  3. Review the findings

    See what was found, how it was found, and what was not checked before you decide.

What the result means

TrustURL never calls a link safe. It tells you what the evidence supports.

  • No known threats detected

    The reputation service has no match and the link shows no warning signs. New threats appear constantly, so this is not a guarantee.

  • Potential risk detected

    A service lists the address, or the link itself has warning signs. Verify the sender before opening it.

  • Analysis incomplete

    An external check could not run, so there is not enough evidence either way.
